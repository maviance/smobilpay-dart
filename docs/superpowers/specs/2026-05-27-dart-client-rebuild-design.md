# Dart Client Rebuild — Design Spec

**Status:** Draft
**Date:** 2026-05-27
**Owner:** Michael Nowag
**Package:** `smobilpay` (pub.dev)
**Repo path:** `/root/s3p-clients/dart`

---

## 1. Purpose

Rebuild `/root/s3p-clients/dart` from a single 112-line HMAC-SHA1 signature
helper (`s3p_signature` package) into a **full Smobilpay partner API v3.2.0
client**, disciplined-port-style, with structural parity to the existing Java
client (`/root/s3p-clients/java`), the in-progress Go client
(`/root/s3p-clients/go`), and the PHP rewrite (`/root/s3p-clients/php`),
matched against the partner OpenAPI spec
(`/root/php-smobilpay-s3p-api/apidocs/s3p_3.2.0_openapi_specs_partner.yml`).

The current repo contents (`lib/s3p_signature.dart`, `example/main.dart`,
`test/ s3p_signature_test.dart`, the pubspec) are replaced wholesale. There is
no consumer migration story to preserve (only the v1 HMAC helper had a public
surface, and it is removed by design).

## 2. Goals & non-goals

### Goals

- Cover every partner-spec endpoint a partner integrator needs to move money
  in and out, sell value-added services, and drive a payment UI from the
  static catalog. Surface mirrors the Java client 1:1 in shape, idiomatic
  Dart calling conventions in form.
- **OAuth 2.0 `client_credentials` only.** HMAC is removed end to end.
- Idiomatic Dart 3: `final` immutable DTOs, sealed exception hierarchy,
  `async`/`await` throughout, `package:http` for transport, null-safety,
  named-parameter constructors. SDK floor `^3.0.0`.
- 80%+ line coverage on `lib/src/` enforced via `dart test --coverage` +
  lcov gate in CI.
- Smoke-test executable (`bin/smoketest.dart`) that consumes the same
  `smoke-test.json` schema as the Java client, so values from a populated
  Java config can be copied verbatim. A `tool/compare_smoketest.dart`
  helper diffs normalized output between Dart and any of Java / Go / PHP.
- Partner-facing README at parity with the Java README — install, quickstart,
  every flow, error handling, configuration reference, onboarding,
  development.
- Published to **pub.dev** as `smobilpay`. `dart pub publish --dry-run`
  passes in CI before tagging a release.

### Non-goals

- Auto-generated client from the OpenAPI spec (explicitly distrusted —
  the previous v1 was largely autogenerated).
- HMAC backward compatibility. The v1 `HMACSignature` class is deleted;
  no compatibility shim.
- Flutter widgets / UI helpers (pure Dart core; Flutter apps consume the
  package like any other Dart library).
- Built-in retry/backoff. Quote expiry (HTTP 498) requires re-quote, not
  blind retry; we surface the error and let callers decide.
- Async iterators / streaming. Operations return `Future<T>`, matching the
  REST shape.
- Unconditional `/v2/collectstd` calls from CI or the smoke test (real
  money movement is never on by default). The smoke test stops at quote
  **unless** a flow block opts in with `collect: true` plus the required
  customer fields — see §8.6 — in which case it executes a real collect
  on the configured environment. CI runs without that opt-in.
- Webhook receiver / callback signature verification helpers.
- A separate `model/` Dart package. Public DTOs ship in `package:smobilpay`,
  co-located with the API group that returns them.

## 4. Public API shape

### 4.1 Construction

Named-parameter constructors give us a builder-like read with no extra
boilerplate. `SmobilpayConfig` validates its inputs in the constructor
and throws `SmobilpayConfigException` on bad input. `SmobilpayClient`
owns the `http.Client` it creates unless the user injects one.

```dart
import 'package:smobilpay/smobilpay.dart';

final client = SmobilpayClient(
  config: SmobilpayConfig(
    baseUrl: Uri.parse('https://api.example.invalid'),
    publicKey: Platform.environment['SMOBILPAY_PUBLIC_KEY']!,
    secretKey: Platform.environment['SMOBILPAY_SECRET_KEY']!,
    apiVersion: '3.0.0',                       // default
    requestTimeout: Duration(seconds: 30),     // default
    tokenRefreshSkew: Duration(seconds: 30),   // default
    // httpClient: customClient,                // optional injection
  ),
);

try {
  final pong = await client.verify.ping();
  final merchants = await client.masterdata.merchants();
} finally {
  client.close();   // closes owned http.Client; no-op if user injected one
}
```

### 4.2 API groups as fields

Method names follow Dart's `lowerCamelCase`. Method ordering and behaviour
mirror Java's `client.<group>()` accessors 1:1.

```dart
// Verify (lib/src/api/verify_api.dart)
Future<Ping>                 client.verify.ping();
Future<Account>              client.verify.account();
Future<List<PaymentStatus>>  client.verify.verifyTransaction({String? ptn, String? trid});
Future<List<PaymentStatus>>  client.verify.historyByPtn(String ptn);
Future<List<PaymentStatus>>  client.verify.historyByTrid(String trid);
Future<List<PaymentStatus>>  client.verify.historyByDateRange({required DateTime from, required DateTime to});

// Masterdata (lib/src/api/masterdata_api.dart)
Future<List<Merchant>>       client.masterdata.merchants();
Future<List<Service>>        client.masterdata.services();
Future<List<Product>>        client.masterdata.products({int? serviceId});
Future<List<Product>>        client.masterdata.vouchers({int? serviceId});
Future<List<Topup>>          client.masterdata.topups({int? serviceId});
Future<List<Cashin>>         client.masterdata.cashins({int? serviceId});
Future<List<Cashout>>        client.masterdata.cashouts({int? serviceId});

// Initiate (lib/src/api/initiate_api.dart)
Future<List<Bill>>           client.initiate.bills({required String merchant, required int serviceId, required String serviceNumber});
Future<List<Subscription>>   client.initiate.subscriptions({required String merchant, required int serviceId, String? serviceNumber, String? customerNumber});
Future<QuoteResponse>        client.initiate.quote(QuoteRequest request);

// Confirm (lib/src/api/confirm_api.dart)
Future<CollectionResponse>   client.confirm.collect(CollectionRequest request);

// Account Validation (lib/src/api/account_validation_api.dart)
Future<bool>                 client.accountValidation.verifyServiceNumber({required String merchant, required int serviceId, required String serviceNumber});
Future<CustomerAccount>      client.accountValidation.validateAccount({required String destination, required int serviceId});

// Token diagnostics
Future<String>               client.tokens.refresh();
OAuth2Token?                 client.tokens.cached;
```

Argument validation:

- `Initiate.subscriptions` throws `SmobilpayConfigException` if both
  `serviceNumber` and `customerNumber` are null (matches Java).
- `Verify.verifyTransaction` throws if both `ptn` and `trid` are null.
- All other required params are enforced by the Dart language via
  `required`-annotated named parameters.

### 4.3 DTOs

Plain Dart classes with `final` fields, named-param constructors, hand-
written `factory X.fromJson(Map<String, dynamic>)`, and `Map<String, dynamic>
toJson()` where the DTO is ever sent on the wire. `==`, `hashCode`, and
`toString` are implemented by hand on each DTO so consumers can compare and
log them without surprise. Most DTOs are read-only response shapes and need
only `fromJson`; `QuoteRequest` and `CollectionRequest` need `toJson`.

Enum fields are decoded into Dart enums via a small shared helper
(`enumByName(values, jsonString, fallback: SomeEnum.unknown)`) that handles
the API's all-caps wire format and gracefully degrades to an `unknown`
variant on unexpected values (matches the lenient decoding posture of the
other clients).

`PaymentItem` is an abstract `interface class` in Dart 3 — `Cashout`,
`Topup`, `Bill`, `Product` (used by vouchers too), `Subscription`, `Cashin`
all implement it, exposing the fields (`payItemId`, `name`, `amountType`,
`amountLocalCur`, `localCur`) used by the smoke-test `quoteAndReport`
helper.

Dates:

- `DateTime` everywhere on the public surface.
- A `LenientDate.parse(String)` helper accepts ISO date (`2026-01-31`),
  offset datetime (`2026-01-31T12:00:00+01:00`), zoned datetime,
  local datetime (`2026-01-31T12:00:00`), and instant
  (`2026-01-31T12:00:00Z`). Matches Java's `LenientLocalDateDeserializer`.
- `DateTime.toUtc().toIso8601String()` is the wire format on outbound
  requests.

### 4.4 Errors

Dart 3 `sealed` lets consumers exhaustively match. All exceptions implement
`Exception` and have informative `toString()`s for logs.

```dart
sealed class SmobilpayException implements Exception {
  final String message;
  const SmobilpayException(this.message);
  @override String toString() => '$runtimeType: $message';
}

final class SmobilpayApiException extends SmobilpayException {
  final int httpStatus;
  final ApiError? error;     // decoded { respCode, devMsg, usrMsg, link }; null if body wasn't JSON
  final String? rawBody;
  SmobilpayApiException(this.httpStatus, this.error, this.rawBody, super.message);
}

final class SmobilpayAuthException extends SmobilpayException {
  final int httpStatus;       // 0 for network failures
  final String? oauthError;   // e.g. 'invalid_client'
  final Object? cause;
  SmobilpayAuthException(this.httpStatus, this.oauthError, this.cause, super.message);
}

final class SmobilpayTransportException extends SmobilpayException {
  final String operation;     // e.g. 'GET /v2/ping'
  final Object cause;
  SmobilpayTransportException(this.operation, this.cause, super.message);
}

final class SmobilpayConfigException extends SmobilpayException {
  SmobilpayConfigException(super.message);
}
```

Idiomatic consumer code:

```dart
try {
  await client.initiate.quote(req);
} on SmobilpayApiException catch (e) {
  if (e.httpStatus == 498) {
    // quote expired — re-quote
  } else if (e.error?.respCode == 41004) {
    // catalog mismatch for voucher endpoint
  } else {
    rethrow;
  }
} on SmobilpayAuthException catch (e) {
  // credentials / OAuth error
}
```

### 5.1 Why this layout

| Choice | Rationale |
|---|---|
| `lib/smobilpay.dart` barrel + `lib/src/` | Dart convention: hide implementation, expose a single public import. |
| API + DTOs co-located per file | Easier to navigate; each file is one concept. Matches Go/PHP twins. |
| `lib/src/model/` for cross-cutting types | `enums`, `payment_item`, `i18n_text`, `commission`, `api_error` are referenced from multiple API files; collecting them avoids cyclic imports. |
| `bin/smoketest.dart` (not `tool/`) | `bin/` is the canonical Dart location for executables exposed via `pubspec.yaml > executables`. |
| `tool/compare_smoketest.dart`, `tool/check_coverage.dart` | `tool/` is the convention for developer-only scripts not shipped to consumers. |
| `test/_support/` (underscore prefix) | Dart convention for non-test helpers inside `test/`. |
| `example/` with multiple files + README | pub.dev scores `example/` discoverability; multiple short examples beat one long one. |

## 6. Authentication design

### 6.1 OAuth 2.0 token manager (`lib/src/auth/oauth2_token_manager.dart`)

- POSTs `Authorization: Basic base64(publicKey:secretKey)` + body
  `grant_type=client_credentials` to `{baseUrl}/oauth/token` with headers
  `Content-Type: application/x-www-form-urlencoded` and
  `Accept: application/json`.
- Parses `{ "access_token": "...", "token_type": "Bearer", "expires_in": N }`.
  If `token_type` is absent or `null` in the response, defaults to `"Bearer"`
  (matches Java's `OAuth2TokenManager.parseTokenResponse`).
- Caches the token in memory; reuses until `now + skew >= expiresAt`.
- Concurrent callers asking for a token while a mint is in flight are de-duped
  via a `dart:async` `Completer`-guarded mutex. One in-flight mint at a time;
  losing callers `await` the same `Future<OAuth2Token>`.
- `refresh()` bypasses the cache to force a fresh mint (used by the smoke
  test's "OAuth 2.0 token refresh" scenario).
- `Clock` is an injected `DateTime Function()` (default `DateTime.now`) for
  deterministic tests.

### 6.2 Token type

```dart
final class OAuth2Token {
  final String accessToken;
  final String tokenType;   // always "Bearer" in practice
  final DateTime expiresAt; // absolute; issuedAt + expires_in seconds

  bool isExpired(DateTime now, Duration skew) =>
      !now.add(skew).isBefore(expiresAt);
}
```

### 6.3 Failure modes

| Failure | Surface |
|---|---|
| Non-2xx from `/oauth/token` | `SmobilpayAuthException(httpStatus, oauthError, cause, message)` |
| Missing `access_token` field | `SmobilpayAuthException(200, null, null, 'missing access_token')` |
| Missing `expires_in` field | `SmobilpayAuthException(200, null, null, 'missing expires_in')` |
| Network / timeout | `SmobilpayAuthException(0, null, cause, 'POST /oauth/token failed: ...')` |
| Body not JSON | `SmobilpayAuthException(200, null, cause, 'token response not valid JSON: ...')` |

## 7. HTTP transport (`lib/src/http/transport.dart`)

- Wraps a `http.Client` injected via `SmobilpayConfig.httpClient` (defaults
  to a new `http.Client()` owned by `SmobilpayClient` and closed in
  `client.close()`).
- Resolves request URI as `baseUrl.resolve(path).replace(query: query)`.
  Trailing `/` on `baseUrl` is normalized at config validation time.
- On every authenticated call:
  1. Asks the token manager for a bearer (auto-mints if expired).
  2. Attaches headers: `Authorization: Bearer <jwt>`,
     `x-api-version: <cfg.apiVersion>` (default `"3.0.0"`),
     `Accept: application/json`.
  3. For `POST` bodies: serializes via `jsonEncode`, sets
     `Content-Type: application/json`.
  4. Applies `cfg.requestTimeout` via `.timeout(...)`.
- On non-2xx:
  - Tries to decode the body as the `ApiError` envelope
    (`{ respCode, devMsg, usrMsg, link }`); on success throws
    `SmobilpayApiException(httpStatus, error, rawBody, message)`.
  - On decode failure throws `SmobilpayApiException(httpStatus, null,
    rawBody, message)` with `error: null`.
- On 2xx: decodes body into the requested type. Decode failures throw
  `SmobilpayTransportException(operation, cause, message)`.

### 7.1 Query parameter builder (`lib/src/http/query_params.dart`)

- Fluent builder with `add(key, value)` semantics:
  - `null` and empty string values **are skipped** (matches Java's
    `QueryParams.add`).
  - `DateTime` values are formatted ISO-8601 with `Z` suffix.
  - `int`, `double`, `bool` go through `toString()`.
- `toQuery() → String` produces the URL-encoded query (or empty string),
  ready to be assigned to `Uri.replace(query: ...)`.

```dart
QueryParams()
  ..add('merchant', merchant)
  ..add('serviceid', serviceId)
  ..add('serviceNumber', serviceNumber)   // null / '' → skipped
  ..toQuery();
```

## 8. Smoke test parity

### 8.1 Schema & resolution

- `smoke-test.json` schema is byte-identical to Java's
  `/root/s3p-clients/java/smoke-test.example.json`. Top-level required
  fields: `baseUrl`, `publicKey`, `secretKey`. Optional `apiVersion`.
  Per-flow blocks (`cashout`, `bill`, `topup`, `voucher`, `product`,
  `subscription`, `cashin`, `verify`, `validate`) — present → exercised,
  absent or `null` → skipped scenario.
- Config resolution order matches Java exactly:
  1. First CLI arg, if present.
  2. `SMOBILPAY_SMOKE_CONFIG` env var, if set.
  3. `./smoke-test.json`.
- A copy of `smoke-test.example.json` ships in the Dart repo so partners
  can copy it and edit.

### 8.2 Scenarios (in order; same as Java)

1. Ping (auth probe).
2. OAuth 2.0 token refresh.
3. Account profile.
4. Merchant catalog.
5. Service catalog (+ VOUCHER/SUBSCRIPTION/verifiable lists).
6. Collection — cash-out (discover + quote).
7. Collection — bill payment (discover + quote).
8. Collection — airtime top-up (discover + quote).
9. Collection — voucher purchase (discover + quote, with 41004 skip).
10. Collection — product purchase (discover + quote).
11. Collection — subscription top-up (discover + quote).
12. Disbursement — cash-in (discover + quote).
13. Account validation — verify serviceNumber (with 40408 skip).
14. Account validation — validate destination (with 401 skip).
15. History — last 7 days.

### 8.5 Cross-client comparison

`dart run tool/compare_smoketest.dart --dart out/dart.log --other out/java.log`
normalizes:

- Timestamps in detail lines → `<ts>`
- Token prefixes → `<token>`
- `quoteId`, `ptn`, `trid` → `<id>`
- Trailing whitespace

Then prints a unified diff. Exit code `0` if logs match, `1` otherwise.
Useful to assert that the Dart client produces identical behaviour to the
Java/Go/PHP twins against the same partner environment.

### 8.6 Opt-in real collection

The smoke test stays quote-only by default. To exercise a real
`POST /v2/collectstd` against an unexpired quote, add the following keys
to the relevant flow block in `smoke-test.json`:

```json
"cashin": {
  "serviceId": 50052,
  "amount": 1000,
  "collect": true,
  "customerPhonenumber": "699999999",
  "customerEmailaddress": "acceptance@maviance.test",
  "serviceNumber": "699999999"
}
```

Required when `collect: true`:

- `customerPhonenumber` — payer's MSISDN for collection flows; recipient
  MSISDN for `cashin` (disbursement).
- `customerEmailaddress` — receipt email per the spec.
- `serviceNumber` — only when the chosen service has
  `isReqServiceNumber: true` (e.g. CMORANGEMOMO cash-in).

Optional pass-through fields the harness wires into the
`CollectionRequest` if present in the config block: `customerName`,
`customerAddress`, `customerNumber`, `trid` (auto-generated as
`dart-smoke-<unix-ms>` otherwise), `tag` (≤ 50 chars), `callbackUrl`
(≤ 255 chars), `cdata`.

Scope for v3.2.0: the opt-in path is wired for **every** collection
flow (`cashout`, `bill`, `topup`, `voucher`, `product`, `subscription`,
`cashin`) — matching the Node.js client. After a successful collect the
harness sleeps 1 s and polls `/v2/verifytx` once to surface the latest
server-side status (matches Node.js; Java omits the poll).

When `collect: true` is set, the scenario label changes from
`(discover + quote)` to `(discover + quote + collect)` so the output —
and the cross-client diff in §8.5 — make the opt-in obvious. The
`collectAndReport` helper prints `status`, `ptn`, `receiptNumber`,
`veriCode`, `priceLocalCur`, `priceSystemCur`, `agentBalance`, `trid`,
`timestamp` from the `CollectionResponse`, plus the polled status from
the follow-up `verifyTransaction`.

**Warning.** Real collects are irreversible from the client. Acceptance
balances drift forever; production money is real money. Leave `collect`
absent or `false` in CI and on shared machines.

## 9. Testing strategy

### 9.1 Unit tests

- `package:test` only. No `mockito`, no `mocktail`. A 50-line
  `FakeHttpClient` in `test/_support/` implements `http.Client` and returns
  prerecorded responses keyed by request URL + method.
- DTO `fromJson` round-tripped against real JSON payloads in
  `test/fixtures/`, sourced from the OpenAPI `examples:` blocks in
  `s3p_3.2.0_openapi_specs_partner.yml`. Keeps decoding honest against
  what the spec promises.
- `OAuth2TokenManager` tested with a frozen `Clock` so expiry / refresh
  logic is fully deterministic. Covers cache hit, cache miss, forced
  refresh, concurrent-mint dedup, all five failure modes from §6.3.
- `HttpTransport` covers: outbound URL / headers / body shape, auth-header
  injection, success decode, `ApiError` envelope decode on 4xx/5xx,
  raw-body fallback on non-JSON 4xx, timeout propagation, decode-failure
  on bad JSON.
- `QueryParams` covers null-skipping, empty-string-skipping, encoding,
  `DateTime` formatting.
- Per-API-group tests assert each method's URL, query-param shape, body
  shape (POST), and that the response payload decodes into the right DTO
  tree.
- Argument-validation tests for `Initiate.subscriptions` and
  `Verify.verifyTransaction` (either/or constraints).

### 9.2 Coverage gate

- Local + CI command:
  ```bash
  dart pub global activate coverage
  dart test --coverage=coverage/
  dart pub global run coverage:format_coverage \
      --lcov --in=coverage/ --out=coverage/lcov.info \
      --packages=.dart_tool/package_config.json --report-on=lib
  ```
- `tool/check_coverage.dart` parses `lcov.info`, computes line coverage on
  `lib/src/`, and exits non-zero if below `80.0%`.
- DTO files containing only `fromJson` factories are still counted; the
  fixture-driven tests are expected to cover them fully.

### 9.3 Integration test (manual)

- `test/integration/end_to_end_test.dart` is `@Tags(['integration'])` and
  excluded from default runs (`dart test`). Reads `SMOBILPAY_PUBLIC_KEY`,
  `SMOBILPAY_SECRET_KEY`, `SMOBILPAY_BASE_URL` from the environment, runs
  the smoke-test scenarios as proper test cases. Run on demand via
  `dart test --tags integration`. Mirrors the Java client's WireMock-based
  end-to-end test in spirit; the Dart equivalent uses the real partner
  environment for now (recorded-cassette mode is a follow-up).

### 9.4 CI

`.github/workflows/ci.yml` runs on push & PR, matrix Dart `stable` + `beta`:

1. `dart pub get`
2. `dart format --output=none --set-exit-if-changed .`
3. `dart analyze --fatal-infos --fatal-warnings`
4. `dart test --coverage=coverage/`
5. Format coverage → lcov; assert ≥ 80%.
6. `dart pub publish --dry-run` (asserts pub-ready on every PR).

## 12. Cross-language behavioural parity

Beyond the smoke-test diff (§8.5), these specific behaviours must match
Java byte-for-byte to keep the four clients interchangeable:

| Behaviour | Specifics |
|---|---|
| Token cache key | In-memory only; no persistence. Key is the `(publicKey, baseUrl)` pair. |
| Token expiry skew | Default 30s; configurable. Java: `tokenRefreshSkew()`. |
| Token type default | `"Bearer"` if absent / null in response. |
| `x-api-version` default | `"3.0.0"`. Configurable. |
| Query param skipping | `null` and empty string skipped. |
| Date format on the wire | ISO-8601 with `Z`. |
| Lenient date parsing | Accepts date, offset datetime, local datetime, instant. |
| `respCode 41004` skip in voucher smoke scenario | Same skip message as Java. |
| `respCode 40408` skip in `verifyServiceNumber` smoke scenario | Same skip message. |
| HTTP 401 skip in `validateAccount` smoke scenario | Same skip message ("restricted endpoint"). |
| Exit codes | `0` / `1` / `2` as in Java's `SmokeTest`. |
| Smoke-test log line shape | Same `RUN ` / `PASS ` / `SKIP ` / `FAIL ` / `Summary:` lines. |
| Real-collect opt-in | `collect: true` on a flow block triggers `POST /v2/collectstd` + one `verifyTransaction` poll. Required fields (`customerPhonenumber`, `customerEmailaddress`, `serviceNumber`-when-needed) validated up-front. Matches Node.js. |
| Auto-generated `trid` | `dart-smoke-<unix-ms>` when `collect: true` and no `trid` in config. Mirrors Java's `java-smoke-<unix-ms>` / Node's `nodejs-smoke-<unix-ms>`. |
